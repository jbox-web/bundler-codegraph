# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`bundler-codegraph` is a Bundler **plugin** (not a library you require) that runs `codegraph init` inside every gem Bundler installs. The point is to make a dependency's source queryable in one call — `codegraph explore --path <gem> "<symbol>"`, or the `codegraph_explore` MCP tool with the same value as `projectPath` — instead of a grep/read loop through `.bundle/ruby/*/gems/`.

## Commands

- Run the full test suite: `bin/rspec`
- Run a single spec file: `bin/rspec spec/bundler/codegraph/indexer_spec.rb`
- Run a single example by line: `bin/rspec spec/bundler/codegraph/indexer_spec.rb:50`
- Lint: `bin/rubocop` (config in `.rubocop.yml`)
- Default rake task (runs specs): `bin/rake`
- `bin/guard` watches files and re-runs specs (see `Guardfile`).

Releases go through `.github/workflows/release.yml`, run by hand from `master` after the version bump in `lib/bundler/codegraph/version.rb` and the dated `CHANGELOG.md` entry are pushed. It calls `rubygems/release-gem`, which runs `rake release` (build, `vX.Y.Z` tag, push) and authenticates to RubyGems.org through Trusted Publishing — no RubyGems secret lives in the repository.

CI (`.github/workflows/ci.yml`) runs Rubocop on Ruby 3.2 and RSpec across Ruby 3.2–4.0 + truffleruby. Minimum supported Ruby is 3.2.0. Coverage is generated by SimpleCov into `coverage/` (HTML + JSON) on every `bin/rspec` run, and the JSON is published to qlty (linters configured in `.qlty/qlty.toml`).

## Navigating this repository

This repository carries its own CodeGraph index (`.codegraph/`, git-ignored —
14 files, 90 nodes). Query it before reaching for `rg`, `find` or `Read` when
locating or understanding code here:

- `codegraph_explore` (MCP tool), or `codegraph explore "<symbol or question>"`
  from the repository root — returns the relevant symbols' verbatim source plus
  the call paths between them, in one call.
- `codegraph sync` picks up changes since the last index, `codegraph status`
  reports what is currently indexed.

`mise.toml` pins the binary for development (`aqua:colbymchenry/codegraph`,
through the jbox-web aqua registry): `mise install` provides it. It is *not*
needed to build or test the plugin: the specs drive a fake
`codegraph` instead, and `bin/rspec` passes with nothing of the sort on `PATH`.

Note that this applies to the plugin's *own* source only. The gems it depends on
are not indexed: they live in the shared GEM_HOME of the mise-managed Ruby
rather than a project-local `.bundle/`, and the plugin is not enabled on its own
`Gemfile`. The rule the README hands to consuming projects — "query the gem's
index instead of reading its files" — has nothing to apply to here.

## Architecture

`plugins.rb` is the file Bundler loads, and the only place that touches Bundler's plugin API. It wires three things: the `GEM_AFTER_INSTALL` hook to `Bundler::Codegraph.after_install`, which only pushes the spec onto `Bundler::Codegraph.pending` (a `Thread::Queue`: Bundler fires that hook from each parallel install worker, and indexing there would stall the install behind `codegraph`); the `GEM_AFTER_INSTALL_ALL` hook to `Bundler::Codegraph.after_install_all`, which drains the queue through `Backfill`; and the `codegraph-index` command to `Bundler::Codegraph::Command`. Bundler 4 fires `after-install` for every gem of the bundle on every `bundle install`, installed or already present, and does not fire `after-install-all` when the install fails. **Keep it that way** — everything under `lib/` must stay loadable, and testable, without Bundler's plugin API. That is why `command.rb` is required from `plugins.rb` only and not from `lib/bundler/codegraph.rb`.

Six collaborators under `lib/bundler/codegraph/`:

1. **`Config`** — the whole configuration, read from the environment so a single `bundle install` can be run with indexing off without editing a file. `BUNDLER_CODEGRAPH` (`0`/`off`/`false`/`no` disables), `BUNDLER_CODEGRAPH_EXCLUDE` (comma-separated globs matched against gem names with `File.fnmatch?`), `BUNDLER_CODEGRAPH_BIN` (path to the binary). There is no *include* list: restricting a run to a few gems means writing negative globs. `Config#executable` resolves the binary against `PATH` lazily, once per `Config`, so the command can check for it before walking the bundle.

2. **`Indexer`** — indexes one directory and **never raises**; every failure mode comes back as a status symbol (`:indexed`, `:synced`, `:failed`, `:failed_before`, `:disabled`, `:excluded`, `:missing`, `:no_ruby`, `:already_indexed`, `:unavailable`). This is load-bearing: it runs from a Bundler hook where an exception would abort the whole `bundle install`. Skip checks are ordered cheapest-first — configuration, then single stats, then the `PATH` lookup (cached by `Config`), and the walk of the gem's tree last. `ruby_sources?` uses the block form of `Dir.glob` to stop at the first `.rb` instead of materializing the whole list. `run` checks for an index again under the lock, since another process may have built it meanwhile, and only syncs with `sync: true`. An index is a `.codegraph/codegraph.db`, the same criterion codegraph uses; a bare `.codegraph/` is a leftover. `codegraph init` creates `.codegraph/` *before* indexing, so `build` removes it in an `ensure` whenever the run does not succeed (a non-zero exit, an exception, `Interrupt`) — otherwise the next run would skip a partial index forever. `--force` renames the existing index to `.codegraph.bundler-codegraph-backup` and restores it when the rebuild fails; a backup found at the start of any run means a rebuild was killed before its `ensure`, and it is restored then. `codegraph` runs with stdin on `/dev/null` (it can prompt on it), stdout discarded, and stderr captured by its `ErrorLog`. `after_install_all` warns through Bundler's UI and the command's per-gem line both point at that log, and only when it exists. `sync: true` (the `codegraph-index` command only; the hook sees every gem on every `bundle install`, so it skips existing indexes) runs `codegraph sync`, which completes an index a killed run left partial.

3. **`Lock`** — an advisory `flock` on a file in `RuntimeDir.path`, wrapping the actual `codegraph` call. `RuntimeDir` is `bundler-codegraph-<uid>` under `Dir.tmpdir`, created `0700` and trusted only when `lstat` shows a directory owned by the current user and closed to group and others: on Linux `Dir.tmpdir` is the shared `/tmp`, where a fixed file name could be pre-created by another user to hold the lock forever. A directory that is ours but left open is closed back to `0700` rather than given up on. An untrusted directory makes the lock run the block unserialized, and both `after_install_all` and the command warn about it. Only opening and locking fall back that way; an error raised by the block itself propagates. `codegraph` already saturates several cores on its own; the queue is drained one gem at a time, and the lock keeps separate processes (two `bundle install`, or one and a `bundle codegraph-index`) from indexing at once. Filesystems without working advisory locks degrade to running unserialized rather than failing.

4. **`Backfill`** — walks a set of specs one at a time, tallying statuses; its keyword options go to every `Indexer` as is, with one shared `Config`; a spec that cannot even be read counts as `:failed` rather than ending the pass. Used by `after_install_all` on the queued specs, and by the command on the whole resolved bundle — the catch-up pass for a `bundle install` that failed before `after-install-all`, and the repair pass (`sync: true`).

5. **`ErrorLog`** — codegraph's stderr for one gem directory, `<gem directory>-<digest of the full path>.log` (two versions, or two directories of the same name, keep a log each) in `RuntimeDir.path`, headed by the full directory it is about, and written as `<log>.part` while codegraph runs: it only takes its name once the attempt failed, so a concurrent `failed_before?` never mistakes a run in progress for a failure. `Indexer#call` discards it once it holds the lock (earlier, it could be another process's log still being written), and `capture` deletes it unless the attempt returned `false` — success, `nil` (codegraph could not be started) and an exception such as `Interrupt` are not codegraph failing. A log that cannot be opened (full disk) does not stop the indexing: codegraph runs without one. A failure message points at the log only when `ErrorLog#kept?` says this very attempt kept it: `Backfill` passes `Indexer#log_hint` to its reporter as a third argument, rather than anyone guessing from what sits on disk. `after_install_all` runs `Backfill` with `skip_failed: true`: a gem whose log names its current directory is reported `:failed_before` and not retried — the hook sees every gem on every `bundle install`, and would otherwise pay the same failure each time. A new version is a new directory; the command never skips. `after_install_all` also prints `bundler-codegraph: indexed <gem>` per gem indexed, a `skipped` line per `:failed_before` gem, and warns once when `RuntimeDir.path` is nil — the lock and the logs are then both off — unless indexing is disabled or the binary missing. Its reporter swallows printing errors (a closed pipe), which must not cost the rest of the queue.

6. **`Subprocess`** — runs codegraph with `Process.spawn`/`Process.wait2` rather than `system`: when Ruby alone is interrupted (SIGTERM to the process, not its group), `system` leaves the child running while the `ensure` cleanups and the lock release proceed, so `run` stops and reaps it first — TERM, then KILL after `STOP_TIMEOUT` — and never signals a child `wait2` already reaped. A child killed by a signal (OOM) or that cannot start gives `nil`, which `ErrorLog` does not record as a failure.

`Command#exec` exits non-zero by raising a `Bundler::BundlerError` (Bundler turns it into the exit status): `Bundler::InvalidOption` on anything but `--force`, `Bundler::PluginError` when the binary is missing (unless indexing is disabled) and, after the whole pass, when any gem failed. `Command#gem_specs` feeds `Backfill` from `Bundler.definition.specs` filtered through `Bundler::Codegraph.dependency?`, which the hook applies too: it drops `bundler` itself (it lives in the Ruby installation) and the project's own spec — a project declaring `gemspec` gets it back with a `Bundler::Source::Gemspec` source (matched on that, since the Gemfile may sit in a subdirectory, as with Appraisal's `gemspec path: '../'`), or, for specs without a source, a `full_gem_path` equal to `Bundler.root` — and indexing it would drop a `.codegraph/` at the project root (and `--force` would wipe an index the user maintains there). It therefore covers the **resolved** bundle, not the contents of `.bundle/ruby/*/gems/` — stale checkouts and superseded versions sitting on disk are not visited, and an unindexed directory there is expected. Gems from a Git source live in `.bundle/ruby/*/bundler/gems/`; `path:` sources are indexed in place, which means a `path:` source tracked by Git needs `.codegraph` in its `.gitignore`.

## Tests

RSpec with `disable_monkey_patching!`, random order and `raise_errors_for_deprecations!` (set in `spec/spec_helper.rb`), plus `--warnings` (the only line of `.rspec`). The specs never invoke the real binary: `build_fake_codegraph` (in `spec_helper.rb`) writes a shell stub that logs its arguments and, on `init`, creates `.codegraph/codegraph.db` — even when told to fail, like the real binary — so the indexer is exercised end to end, exit-status and cleanup paths included, against a real temporary tree. Its `stderr:` and `probe_stdin:` options cover the error log and the closed stdin. Specs that reach `RuntimeDir` point `Dir.tmpdir` at the example's temporary root, so a run leaves nothing in the real one. SimpleCov tracks `lib/` and `plugins.rb` (minus `version.rb`, loaded by the gemspec before SimpleCov starts), so a file no spec loads shows up as uncovered.
