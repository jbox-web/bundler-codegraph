# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`bundler-codegraph` is a Bundler **plugin** (not a library you require) that runs `codegraph init` inside every gem Bundler installs. The point is to make a dependency's source queryable in one call — `codegraph explore --path <gem> "<symbol>"`, or the `codegraph_explore` MCP tool with the same value as `projectPath` — instead of a grep/read loop through `.bundle/ruby/*/gems/`.

## Commands

- Run the full test suite: `bin/rspec`
- Run a single spec file: `bin/rspec spec/bundler/codegraph/indexer_spec.rb`
- Run a single example by line: `bin/rspec spec/bundler/codegraph/indexer_spec.rb:50`
- Lint: `bin/rubocop` (config in `.rubocop.yml`)
- Default rake task (runs specs): `bin/rake`
- `bin/guard` watches files and re-runs specs (see `Guardfile`).

CI (`.github/workflows/ci.yml`) runs Rubocop on Ruby 3.2 and RSpec across Ruby 3.2–4.0 + truffleruby. Minimum supported Ruby is 3.2.0. Coverage is generated by SimpleCov into `coverage/` (HTML + JSON) on every `bin/rspec` run, and the JSON is published to qlty (linters configured in `.qlty/qlty.toml`).

## Navigating this repository

This repository carries its own CodeGraph index (`.codegraph/`, git-ignored —
14 files, 90 nodes). Query it before reaching for `rg`, `find` or `Read` when
locating or understanding code here:

- `codegraph_explore` (MCP tool), or `codegraph explore "<symbol or question>"`
  from the repository root — returns the relevant symbols' verbatim source plus
  the call paths between them, in one call.
- `codegraph sync` picks up changes since the last index, `codegraph status`
  reports what is currently indexed.

The repository does not pin the binary — install it separately, see the README.
It is *not* needed to build or test the plugin either: the specs drive a fake
`codegraph` instead, and `bin/rspec` passes with nothing of the sort on `PATH`.

Note that this applies to the plugin's *own* source only. The gems it depends on
are not indexed: they live in the shared GEM_HOME of the mise-managed Ruby
rather than a project-local `.bundle/`, and the plugin is not enabled on its own
`Gemfile`. The rule the README hands to consuming projects — "query the gem's
index instead of reading its files" — has nothing to apply to here.

## Architecture

`plugins.rb` is the file Bundler loads, and the only place that touches Bundler's plugin API. It wires two things: the `GEM_AFTER_INSTALL` hook to `Bundler::Codegraph.after_install`, and the `codegraph-index` command to `Bundler::Codegraph::Command`. **Keep it that way** — everything under `lib/` must stay loadable, and testable, without Bundler's plugin API. That is why `command.rb` is required from `plugins.rb` only and not from `lib/bundler/codegraph.rb`.

Four collaborators under `lib/bundler/codegraph/`:

1. **`Config`** — the whole configuration, read from the environment so a single `bundle install` can be run with indexing off without editing a file. `BUNDLER_CODEGRAPH` (`0`/`off`/`false`/`no` disables), `BUNDLER_CODEGRAPH_EXCLUDE` (comma-separated globs matched against gem names with `File.fnmatch?`), `BUNDLER_CODEGRAPH_BIN` (path to the binary). There is no *include* list: restricting a run to a few gems means writing negative globs.

2. **`Indexer`** — indexes one directory and **never raises**; every failure mode comes back as a status symbol (`:indexed`, `:failed`, `:disabled`, `:excluded`, `:missing`, `:no_ruby`, `:already_indexed`, `:unavailable`). This is load-bearing: it runs from a Bundler hook where an exception would abort the whole `bundle install`. Skip checks are ordered cheapest-first — configuration before the filesystem walk and the `PATH` lookup. `ruby_sources?` uses the block form of `Dir.glob` to stop at the first `.rb` instead of materializing the whole list. `--force` does `rm_rf` on the existing `.codegraph/` before re-running.

3. **`Lock`** — an advisory `flock` on a file in `Dir.tmpdir`, wrapping the actual `codegraph init` call. `codegraph` already saturates several cores on its own and Bundler fires `after-install` from each of its parallel install workers, so without this a cold `bundle install` would spawn `BUNDLE_JOBS` indexers at once. Filesystems without working advisory locks degrade to running unserialized rather than failing.

4. **`Backfill`** — walks a set of specs one at a time, tallying statuses. Exists because the hook only fires for gems Bundler *actually installs*: a bundle already in place would otherwise never get an index.

`Command#gem_specs` feeds `Backfill` from `Bundler.definition.specs` minus `bundler` itself. It therefore covers the **resolved** bundle, not the contents of `.bundle/ruby/*/gems/` — stale checkouts and superseded versions sitting on disk are not visited, and an unindexed directory there is expected. Gems from a Git source live in `.bundle/ruby/*/bundler/gems/`; `path:` sources are indexed in place, which means a `path:` source tracked by Git needs `.codegraph` in its `.gitignore`.

## Tests

RSpec with `disable_monkey_patching!`, random order, `raise_errors_for_deprecations!` and `--warnings` (see `.rspec`). The specs never invoke the real binary: `build_fake_codegraph` (in `spec_helper.rb`) writes a shell stub that logs its arguments and creates the `.codegraph` directory, so the indexer is exercised end to end — including the exit-status path — against a real temporary tree.
